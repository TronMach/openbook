# Server, API and platform

Developer notes moved out of `CLAUDE.md` (index there). Read this file before changing this area; keep it up to date in the same commit.

## Multi-user and server (V1.8)

- `UserRole` (ViewOnly < Standard < Accountant < Admin) on `User`, plus `IsActive`; users are deactivated, never deleted. Changing a role or deactivating rotates the security stamp, so sessions end. `UserService` keeps at least one active admin and refuses changes to yourself. Inactive users sign in like a wrong password.
- Access is decided in one place: `Web/Security/AccessRules.Required(path, method)` (first matching prefix rule; reads need ViewOnly, changes and "write pages" — `new`, `edit`, `import`, `apply`, `pay`, `reconcile`, `feed`, recurring editors, … — need Standard), enforced by `AccessMiddleware` for pages, form endpoints and the API (403 JSON for `/api`, `/access-denied` redirect otherwise). A new page or endpoint that changes the books or settings needs a rule; add a case to `AccessRulesTests.Access_rules_map_paths_to_roles` (in `ApiAccessTests.cs`; a class of its own because `ApiAccessTests` starts a web app per case). Hide nav links with `User.CanReach(href)`.
- The role is a claim in the cookie; cookies without one (from before V1.8) are rejected so people sign in again.
- API keys (`ApiKey`, `ApiKeyService`): `Authorization: Bearer obk_…`, SHA-256 hash stored, shown once, act as their user with the user's role, revoked not deleted, last use recorded at most once a minute. The default auth scheme is a policy scheme picking the bearer handler (`ApiKeyAuthenticationHandler`) or the cookie.
- OpenAPI at `/api/openapi/v1.json` (anonymous; Microsoft.AspNetCore.OpenApi). `/api/me`, `/api/users`, `/api/api-keys`, `/api/webhooks`, `/api/backup` cover what the new pages do.
- Webhooks are fed by the audit log: `WebhookDispatcher` (run every 5 s by `WebhookDispatchService`) turns audit records after each subscription's `Cursor` into `WebhookDelivery` rows, stopping at a gap in the ids until it's `GapWait` (5 minutes) old, since on PostgreSQL a long transaction's ids show only at commit (event type `{entity_type}.{action_snake}`, payload with before/after snapshots, fixed at creation), then posts due ones via `IWebhookSender` (`HttpWebhookSender`: 10 s timeout, no redirects) with `OpenBook-Signature: t=…,v1=HMAC-SHA256(secret, "t.body")` (`WebhookSignature`). Retries back off 1 m → 12 h, 6 attempts, then Failed (redeliver by hand). Secrets are stored with `ISecretProtector`. Anything audited is an event, so keep audit snapshots free of secrets. Outbound calls to addresses people type in (webhooks, SimpleFIN claim/access URLs) use `Net.PublicNetwork.Handler(OutboundPolicy)`: its connect callback resolves the host and refuses (`PrivateNetworkException`) when any address is loopback, private, link-local, shared, multicast or reserved (IPv4-mapped and NAT64 judged as IPv4), connecting to the checked address so DNS can't switch in between. `OpenBook:Outbound:AllowPrivateNetworks=true` turns it off (the host registers `OutboundPolicy`). S3 backup and SMTP hosts are admin settings and may be local; fixed hosts (Stripe, Shopify, Google Fonts, Claude) don't need it.
- Concurrency: records two people (or a person and a background job) may change at once carry a shadow `Version` concurrency token (`OpenBookDbContext.Versioned`: documents with balances or status, bill payments, recurring templates, feed lines, payment links, payouts, items), bumped by every save that modifies the row, or adds, changes or removes one of its owned rows (`TouchOwners`: what's used of a credit is summed from its applications). A stale save, or a unique number (entry or document number) taken in between, throws `ConcurrencyConflictException` (`save.conflict`, API 409) and saves nothing. `Operations.RunAsync` (new scope) and the `/api` filter (`DiscardPending`, raw bodies rewound) run the operation again, up to `ConflictRetry.Attempts`, only while the scope hasn't saved anything (`IUnitOfWork.HasSaved`); static form endpoints show the message. A new entity people may change concurrently goes in `Versioned` (migration in both projects). Stock: every save adding `InventoryMovement`s bumps those items' versions (`SaveChangesAsync` touches them), so two documents planned from the same stock can't both save; this relies on plans loading the item (tracked) before reading its movements, as `InventoryService` does.
- Stale forms: the token only catches overlapping saves, so edit pages note the version when they open and check it first (`IRecordVersions`, `EnsureUnchangedAsync`, `save.stale`; read it before loading the record). Interactive: `Ops.VersionAsync<TRecord>(id)` and `Ops.ChangeAsync<TRecord, TService, T>(id, _version, …)`; static: a hidden `Input.Version` and `Versions.EnsureUnchangedAsync`. Not on settings pages. API: `ApiVersions` (Api, a filter on the `/api` group): routes in `ApiVersions.Routes` (a record route up to `{id`, and its type) answer GET with `ETag: "v{n}"` and refuse a write sending a stale `If-Match` with 412 `save.stale`; no `If-Match` = no check; a change returns the new tag. `IRecordVersions.GetAsync(type, id)` (extension). A new edit page of a `Versioned` record does the same, and its API route goes in `ApiVersions.Routes`.
- Encryption at rest: SQLite runs on SQLCipher (`SQLitePCLRaw.bundle_e_sqlcipher` 2.1.11 with `Microsoft.EntityFrameworkCore.Sqlite.Core`). `OpenBook:EncryptionKey` becomes the connection's `Password`; backups and safety copies use the same key, and restore only accepts backups with that key. `SqliteEncryption` converts files with `sqlcipher_export` (triggers included).
- PostgreSQL: `OpenBook:Database=Postgres` (or a connection string starting `Host=`). Migrations live in `OpenBook.Infrastructure.Postgres` (`InitialPostgres` creates the whole current schema; ledger triggers as PL/pgSQL functions in `InitialPostgres.Triggers.cs`, same names and messages, plus a TRUNCATE guard on AuditRecords). Every schema change needs a migration in both projects, and trigger changes in both dialects. In-app backup/restore is SQLite-only (`UnsupportedBackupService` says to use pg_dump). Store `DateTimeOffset`s in UTC (Npgsql rejects other offsets). The whole integration suite passes on PostgreSQL 17. Tests that touch the database directly catch `System.Data.Common.DbException` and use SQL both providers accept (TRUE/FALSE, explicit `"Basis"`).
- Containers: Data Protection keys go to `OpenBook:DataProtectionKeys` (Docker: `/data/keys`) so cookies and stored secrets survive restarts. The image installs DejaVu fonts for PDFs and `libgssapi-krb5-2` (Npgsql loads it on connect) and runs as the non-root `app` user. The build copies `.editorconfig`, which marks migrations as generated code; without it the analyzers fail the Release build. Image and compose stack verified with Docker Desktop (Linux containers); on a fresh PostgreSQL database EF logs one failed `__EFMigrationsHistory` query before creating the schema, which is expected.
- Audit entity types: api_key, webhook (users were already `user`).
- Diagnostics (`Web/Diagnostics`): `FileLoggerProvider` (made by the container so it's disposed; one file per UTC day `openbook-yyyyMMdd.log`, kept 14 days, written by one background writer from a bounded queue; Microsoft/System categories at Warning and up) also keeps the last 100 warnings and errors in memory. `LogFolder.For`: `OpenBook:LogDirectory`, else `logs` beside the backups folder (Docker: /data/logs), else beside a SQLite file, else the content root. `JobStatus` (singleton, in memory) holds each background job's last run, duration and last failure: every hosted service records its run (failures reported per item count too), and `RecurringPostingService` records each step. Page `/settings/system` (admin).

## CLI and installable app (L9, slice 1)

- `src/OpenBook.Cli` (assembly `openbook`, packable as a dotnet tool, no project references): `CliApp` turns commands into API calls with `Authorization: Bearer` (`--closing-password` adds `X-Closing-Password`). Commands: `config`, `whoami`, `list <what>` (`CliApp.Lists` maps names to API paths; prints `PreferredColumns` as a `TextTable`, `--json` raw), `report <key> [--query] [--format table|json|csv|xlsx|pdf] [--out]` (uses `/api/reports/{key}/table` and `/export`), `import <source> <file> [--dry-run]`, `export`/`backup --out`, and raw `get|post|put|delete <path> [--data json|@file] [--out]` (paths get `/api` prepended). Exit codes: 0 ok, 1 server refused or unreachable, 2 command mistake. Tests inject a client factory (`CliTests` against `WebApplicationFactory`). The admin-side commands (`reset-password`, `encrypt-database`) stay in the web app because they work on the company file directly.
- PWA: `wwwroot/manifest.webmanifest` (linked from `App.razor` with theme color and icons in `wwwroot/icons`, drawn by a script: open book on the accent green; maskable one inside the safe zone), `wwwroot/sw.js` registered from `shortcuts.js` in secure contexts. The service worker caches only static files (stale-while-revalidate) plus `offline.html`; pages always come from the network (offline page when unreachable); `/api` and `/_blazor` are never touched. Bump `VERSION` in `sw.js` when the cached shell changes.

## Add-ins and scoped API keys (L9, slice 2)

- Add-ins (`Application/Plugins/Plugins.cs`): a DLL implementing `IOpenBookPlugin` in its own folder under `OpenBook:Plugins:Path` (default `plugins`). `Web/Plugins/PluginLoader` loads each folder at startup in its own `AssemblyLoadContext` (OpenBook and framework assemblies come from the host), skips folders with a `disabled` file, and loads nothing with `OpenBook:Plugins:SafeMode=true` or `--safe-mode` (stripped from the args before configuration). The `PluginRegistry` singleton is registered before `AddOpenBookApplication` (which `TryAdd`s an empty one for tests). `Register` runs against a pending registry, so a plugin that throws or collides with a key leaves nothing behind (`PluginState.Failed`).
- Slots: `AddReport` (a `ReportDefinition` + run function with a scoped service provider; keys can't match built-ins) and `AddImporter` (key, label, help, accept, `byte[] → MigrationData`). `ReportCatalog.BuiltIn`/`FindBuiltIn` are the static built-ins; inject `ReportCatalog` and use `All`/`Find` to include add-ins. `MigrationImportService.Sources()` and the string-keyed `PreviewAsync`/`ImportAsync` take a built-in `MigrationSource` name or an add-in key (the import page, API and CLI use them). Payment and bank-feed providers aren't slots yet: their provider fields are enums (see the Square/PayPal/Plaid backlog item).
- Add-in API version (2026-11-12): `PluginApi.Version`/`Oldest` (Application/Plugins); `IOpenBookPlugin.ApiVersion` (default 1, never changed; add-ins return `PluginApi.Version`, a constant compiled into them). `PluginRegistry.Load` reads it before `Register` and records a refusal (`PluginApi.Refusal`: newer than this OpenBook, or older than `Oldest`) as Failed without running the add-in; a `MissingMemberException`/`TypeLoadException` from an add-in's code (registering or discovering) becomes "built for a different version" (`PluginApi.Explain`). `PluginInfo.ApiVersion`. Policy: `docs/dev/api-stability.md`. Tests: `PluginApiTests` (no database).
- Page `/settings/plugins` (admin): folders, state, what each adds; turning one off/on writes/deletes the `disabled` file (audited on the company) and applies at restart. Plugin routes take only a plain direct subfolder name.
- Scoped API keys: `ApiKey.Scopes` ("area:read"/"area:write", null = everything the user may do; `ApiScopes.Areas` maps areas to API path prefixes). `ApiKeyService.AuthenticateKeyAsync` returns the scopes; the bearer handler adds `obk:scoped` / `obk:scope` claims; `AccessMiddleware` refuses (403 `auth.scope`) any request outside the key's areas before the role check, so limited keys never reach users, keys, webhooks or non-API pages; nor anything `Required` rates Admin (`AccessRules.ClosedToLimitedKeys`: sign-in, email, online payment settings), except `/api/backup` and `/api/export`, which the `data` area gives on purpose. `ApiScopes.AreaOf` goes by the longest prefix. `/api/me` and OpenAPI are always allowed. API parity (2026-11-07, C297): `POST /api/attachments?entityType=&entityId=&fileName=` (raw body) and `GET /api/attachments/{id}/content` (read with the record's area), `/api/sales/portal-links` (token once; in the idempotency `SecretPaths`), grant `receipts|recognitions|requests/{line}/void` and `reopen` (rows in `GrantResponse`), channel `GET /orders/{id}`, `/orders/{id}/dismiss|restore|returns`, `/returns/{id}[/void]`, `GET|PUT /api/projects/time/week`, `GET /api/accountant/package`, `POST /api/nonprofit/statements/{year}/email`, `PUT /api/banking/connections/{id}/name`, `GET /api/purchases/ach/vendors/{id}` (masked). Restore is left out of the API on purpose. The API keys page and `POST /api/api-keys` take scopes. Admins see and revoke anyone's keys on `/settings/users/{id}` and through `GET /api/users/{id}/api-keys`, `DELETE /api/users/{id}/api-keys/{keyId}`. Add a new API area's prefixes to `ApiScopes.Areas`, or limited keys can't reach it.

## Languages and regions (L9, slice 3)

- `Web/Localization/AppCulture`: `UseRequestLocalization` picks the region (`CurrentCulture`: date and number formats) and language (`CurrentUICulture`) from the `.AspNetCore.Culture` cookie (set by `/account/region`), else the browser's Accept-Language, else en-US. Only listed values are accepted. Interactive circuits keep the culture of the request that started them.
- Regions are only those writing numbers "1,234.56": amount fields are pre-filled with `ToString("0.00")` in the current culture and parsed with "." as the decimal point, so a comma-decimal region would misread amounts. Adding one means auditing every amount field (`LocalizationTests` checks the list).
- Text: `@L["English text"]` (`IStringLocalizer<SharedResource>`, injected in `Components/_Imports.razor`), keyed by the English text, so untranslated text shows in English. Formatting arguments go in the call (`@L["Starts in {0}", month]`), never concatenated. The neutral catalog `Resources/Localization/SharedResource.resx` is generated by `python tools/extract-strings.py` (a test fails when it's stale, or when two texts differ only in case: resource names ignore case, so reword one); a translation is `SharedResource.{lang}.resx` beside it plus the language in `AppCulture.Languages`. Converted so far: navigation, sign-in, home, dashboard, language page, password and sessions, settings, search, access denied, not found, the three recurring template lists and editors, new invoice and invoice detail. Text inside a sentence with a link or bold word stays English until the sentence can be one key (don't split sentences into fragments). Convert pages as they're touched.

## Offline capture (L9, slice 4)

- Device side: `wwwroot/capture.html` + `capture.js`, a static page (no data in the HTML, so the service worker may cache it and serve it offline; it's in `SHELL` with `capture.js` and `/app.css`). Drafts (time, mileage, expense with optional photo, receipt photo, invoice or estimate) and the cached lists live in IndexedDB `openbook-capture`, sealed with an AES-GCM key generated non-extractable and kept in the same database. Encrypt before opening an IndexedDB transaction (a transaction closes if it awaits anything else). Each draft gets `crypto.randomUUID()`. Sync on load, on `online`, every minute and on "Send now", one tab at a time (Web Locks), in requests of at most 200 drafts and 20 MB (Kestrel stops a body at 30 MB; photos are limited to 5.5 MB, under `CaptureDraft.MaxPayload` once base64); 401 keeps drafts and asks to sign in; 410 wipes the database. The JS checks mirror the server's main rules; the server decides.
- Server side: `CaptureDevice` (per user, revoked never deleted; audit `capture_device`) and `CaptureDraft` (key = the device's id, so a resend returns the stored outcome; audit `capture_draft` naming the device). Each draft's row and what it became are one `IUnitOfWork` transaction, row first, so a send cut off, or made from two tabs, can't enter a draft twice (`RetryAsync` likewise, through `TryTakeWaitingAsync`); a refusal rolls back, then records the draft as needing attention. A draft over `MaxPayload` is kept without its photo, needing attention, and stops nothing else. An expense entered without its photo (`Error` holds the note) keeps the photo in `Payload`, since the device deletes its copy: `/capture` lists it under "Entered, with a note" with `GET /capture/drafts/{id}/photo`, and `AcknowledgeAsync` drops both. `CaptureService.SyncAsync(userId, deviceId, drafts)` enters each draft in its own DI scope through `TimeService`, `MileageService`, `BankingService` (+ `AttachmentService` for a photo), `ReceiptService`, `InvoiceService` or `EstimateService` (kinds `Invoice`/`Estimate`: customer, date, memo and item lines; a line without a rate is `AutoPrice`d, and the server numbers and taxes it, so an invoice posts on sync); a `DomainException` leaves it `NeedsAttention` with the message. Entered drafts drop their photo from the stored payload (`Compact`); `CaptureDrafts.Payload` is left out of the data export. A revoked device gets `capture.device_revoked` (410 from the API). A device records the sign-in session that registered it (`CaptureDevice.SessionId`; null through an API key), and revoking it ends that session unless it's the caller's own. The revoke form's "also sign out my other sessions" box, like the "Sign out all other sessions" button on `/account/password`, calls `AuthService.EndOtherSessionsAsync` (new security stamp, so every other cookie is refused on its next request) and re-issues the current browser's cookie. A signed-out device asks the anonymous `GET /capture/device-status/{id}` (`IsRevokedAsync`; unknown ids answer false) when it gets 401, and wipes itself if revoked. API keys aren't affected by ending sessions. `ListsAsync` gives what the forms need (workers, customers, services, active items, pay-from and expense accounts, vendors, this year's mileage rate), never balances or secrets.
- API `/api/capture` (`/devices`, `/lists`, `/sync`, `/drafts`, retry/dismiss); scope area `capture`. Page `/capture` (drafts needing attention: retry, dismiss; the user's devices: remove access); form posts are mapped in `Program.cs`.

## Hardening (2026-11-02)

- Rate limits (`Web/Security/RateLimits.cs`, `AddOpenBookRateLimits`, `app.UseRateLimiter()` early): one global partitioned limiter, sliding one-minute windows per remote address; sign-in posts (`/login*`, `/invite/*` POST) and `/login/sso` at `OpenBook:RateLimits:SignInPerMinute` (20), anonymous links (`/portal/`, `/pay/`, `/invite/`, `/capture/device-status/`, `/hooks/`) at `LinksPerMinute` (120); 0 turns one off; everything else unlimited. 429 with Retry-After, JSON for `/api` and `/hooks`, a short page otherwise. A new anonymous path that takes tokens or passwords belongs in one of the lists.
- Idempotency keys (`Web/Security/IdempotencyMiddleware.cs` after `AccessMiddleware`; `IIdempotencyStore` → `EfIdempotencyStore`, table `IdempotentRequests`, own DB session per call): `/api` writes with `Idempotency-Key` reserve (caller, key) with a SHA-256 of method, path, query and body; repeats replay the kept response (`Idempotency-Replayed: true`), a different request with the key is 422 `idempotency.key_reused`, one still running 409 `idempotency.in_progress` (for `AbandonedAfter`, 15 minutes, then the key is free); refusals (4xx, where nothing was saved), 5xx and bodies over 1 MB aren't kept, and a kept answer keeps its `Location` and `Content-Disposition`. `SecretPaths` (API keys, invitations, webhooks, capture) ignore the header so one-time secrets are never stored; add any new endpoint that returns a secret there. Kept a day (`IdempotentRequest.KeptFor`), purged by the hourly job; `Body` is left out of the data export. CLI `--idempotency-key`.
- Job leases (`IJobLeases` → `EfJobLeases`, table `JobLeases`, expiry as Unix ms since SQLite can't compare DateTimeOffsets): every hosted service asks `TryAcquireAsync(job, ttl)` each run (hourly 90 min, scheduled emails 3 min, webhooks 1 min, bank and channel sync 90 min, backups 45 min); one conditional UPDATE renews or takes a lapsed lease, else the first INSERT wins. Holder = machine:process:random. A new background job takes a lease too.
- `OpenBook.Web healthcheck` (`Cli/HealthCheckCommand.cs`) before the host is built; the Dockerfile's `HEALTHCHECK` uses it.
- `ServerHardeningTests`.
- Limits: `Money.MaxAmount` and `SalesLine.MaxRateOrQuantity` refuse what the database's whole cents can't hold, and a number or date out of range is 400 `request.value_out_of_range` from the API. Report dates are held inside `DateRanges.FirstYear`..`LastYear`.
- Every signed-in form post binds a form (`IFormCollection _` when it reads nothing), which is what makes minimal APIs check the antiforgery token; `Every_signed_in_form_post_checks_the_antiforgery_token` walks the routes. `NotFoundMiddleware` answers unreadable query values with not found, and a post to a form the page no longer draws by going back to the page.
- `IUnitOfWork.BeginSnapshotAsync` reads one moment of the books without taking SQLite's write lock (exports, the books check). `IAccountInUse` says why an account must stay active. `AccountService.CreateUsualAsync` is for accounts OpenBook makes on first use. `JobLeaseRelease` gives up leases at a clean stop and must never throw: the test host can dispose services first.
- `ApiErrorMiddleware`: `/api` never gets the not-found page, and an error with no body gets JSON with `code` `http.{status}`. `Operations.RunAsync` turns a database or disk failure into `save.failed`, so an interactive page keeps what was typed. `FormFont.Check` reads the table directory, so a damaged font is refused on upload.
- `PageSmokeTests` (2026-11-03) opens every page, every record page with an id nothing has, every API read and write (empty body) and every form post (empty form) in an empty company, and fails on any 5xx. `NotFoundMiddleware` (Web/Diagnostics) answers an `EntityNotFoundException` outside the API with the not-found page; the API filter answers an `ArgumentNullException` (a list left out of the body) with 400 `request.value_missing`. Never `return;` inside page markup while an element is open (the render fails): use `else`.
