# Setup, backups, installs and moving in

Developer notes moved out of `CLAUDE.md` (index there). Read this file before changing this area; keep it up to date in the same commit.

## Company setup and backup (from the company section)

- One company per database, created by `/setup` (`CompanySetupService`), then `/accounts` for a starter chart. Setting up from an export: "Read the file" (multipart, handler `read`) gets the company's details with `MigrationReaders.ReadCompany` (qbXML CompanyRet, QBO CompanyInfo/Preferences, GnuCash book options; IIF and CSV have none) to fill the form, and `SetupState.Hold` keeps the file (one, an hour, before setup only; the form carries its token); "Create company and import" runs `MigrationSetupService.SetUpAsync`: setup and import in one transaction (`EfUnitOfWork` joins an open one), nothing kept if a row has an error, audited as the new owner (the page sets `HttpContext.User` to the username first). Home currency comes from the `Company` row; ledger services throw `company.not_set_up` before setup. `SetupGateMiddleware` routes pages to `/setup` until then.
- Backup = SQLite online backup API → plain `.openbook.db` file. Restore validates (integrity, known migrations, triggers present, company present, ledger balanced), migrates and validates a temporary copy, writes a safety copy to `backups/` next to the company file, then copies over the live DB in place, so a failed migration leaves the books as they were. At start on SQLite, `SqliteBackupService.PrepareToMigrateAsync` clears a stale `__EFMigrationsLock` row and, when migrations are waiting on an existing company, takes a `pre-upgrade-…` copy (last three kept). A new trigger must be added to `SqliteLedgerTriggers.Names` or restore won't check for it.

## Portability and UX (V1.9)

- Chart CSV imports: a `Non-Posting` row is `ImportRowStatus.Skipped`, and a Tax line value that isn't one of ours is ignored, so a QuickBooks chart export comes in. In the migration pipeline an item without an income account is Skipped, not an error: no transaction needs it.
- Imports post journal entries with `JournalEntry.ImportSource` ("ledger.import", a journal source, so voided from the journal), `SourceId` = the import batch. `JournalImportService`: journal entry CSV (date, account by full name or number, debit/credit or signed amount, optional entry number; without one, lines group until they balance; dates' order detected per column) and opening balance CSV (natural-sign balance or debit/credit, through `OpeningBalanceService`). Preview first; any error stops the whole import. `VoidBatchAsync` undoes a batch (every standing entry voided in one save, or none: "Undo the whole import" on an imported entry's page, `POST /api/journal-entries/imports/{batchId}/void`); records a move-in created stay. `PostingEngine.SaveAsync` saves staged entries for callers without a document.
- `IifImportService` reads QuickBooks Desktop IIF (tab-separated, `!TYPE` headers): ACCNT, CUST, VEND, INVITEM and TRNS/SPL/ENDTRNS. Existing names are skipped; NONPOSTING accounts, estimates/orders and discount/subtotal/tax items are skipped; transactions become journal entries (positive = debit), so A/R and A/P aging won't list them. It creates records through the normal services inside an `IUnitOfWork` transaction (EF: `EfUnitOfWork`; `OpenBookDbContext.SaveChangesAsync` joins an open transaction), so the file imports whole or not at all.
- Full data export (`IDataExporter` → `DataExporter`): a ZIP with one CSV per table built from the EF model (raw `SELECT` with quoted identifiers, values as stored), `attachments/`, and a generated README documenting every table and column (types as stored, cents/ten-thousandths, foreign keys). Secrets are excluded by table/column in `DataExporter.Excluded` (password and token hashes, protected secrets, vendor tax IDs, ACH file contents, attachment bytes); add new secret columns there. Admin only (`/export/download`, `/api/export`).
- Notes (`Domain/Notes/Note`, `NoteService`): free text on any record in `NoteService.EntityTypes` (attachment types plus account and item), audited on the owning record as `NoteAdded` / `NoteRemoved`. Put `<Notes EntityType=… EntityId=… />` beside `<Attachments>` on record pages; it posts to `/notes` (Web endpoint, antiforgery).
- Register for any account: `/accounts/{id}/register` (general ledger lines in the account's natural direction with a running balance) with a quick-entry row that posts a two-line journal entry (accountant role).
- `wwwroot/shortcuts.js`: theme choice (Auto/Light/Dark in `localStorage` `ob-theme`, `data-theme` on `<html>`, set early by an inline script in `App.razor` and re-applied after enhanced navigation) and keyboard shortcuts (`/` search, `?` help, `g`/`n` + key to go or create, Ctrl+Enter submits the current form, Alt+Q quick entry; ignored while typing). Dark colors live under `:root[data-theme="dark"]` and the `prefers-color-scheme` block (skipped when `data-theme="light"`); keep both in step.

## Migration and scheduled backups (L8)

- `ImportedBefore` keeps imports from repeating: a transaction or journal CSV entry with the date, memo, accounts and amounts of a standing `ledger.import` entry is `Exists` (each standing entry answers for one incoming, so identical ones in a file both come in once; undoing an import frees them).
- The planner runs the same rules as the import (`Vendor.Create`, `Account.Create`, `Item.Create`, inactive accounts), so a clean preview imports. An all-zero transaction is Skipped. An account whose number is taken comes in without one (`#1234` references still reach it).
- Moving in from another program goes through one pipeline (`Application/Import/Migration`): a reader turns the export into `MigrationData` (accounts, customers, vendors, items, transactions in OpenBook's terms), and `MigrationImportService` previews it against the books and imports it all-or-nothing in one `IUnitOfWork` transaction (the old IIF importer's rules: existing names are left alone, transactions become `ledger.import` journal entries, one batch per file). `MigrationReaders.Read(source, bytes, homeCurrency)` picks the reader. Readers never touch the database; accounts named "#1234" are resolved by account number in the planner.
- Jobs come in as sub-customers billed with their customer (`SourceCustomer.Parent`, the source's full name; the customer CSV takes a Parent column or "Customer:Job" names, parents anywhere in the file). Inventory parts come in tracked (`ItemType.Inventory`, `SourceItem.Quantity`/`UnitCost`) and `OpeningStockService.RecordAsync` brings their stock in: an adjustment against Opening Balance Equity and, with `alreadyInBooks`, a journal entry taking that value back out, since the history already holds it. CSV imports, each preview then all or nothing: `OpeningStockImportService` (`/inventory/opening-stock`), `OpenDocumentImportService` (`/import/open-documents`: real invoices on an "Opening balance" item, and bills, warning when the A/R or A/P accounts hold money no document explains), `ProjectImportService` (`/time/people/import`: people, rate card, unbilled time). API under `/api/import` (`/open-documents/{kind}`, `/opening-stock`, `/projects/{kind}`).
- Readers: `IifImportService.Read` (QuickBooks Desktop IIF; the service is now a thin wrapper), `QbxmlReader` (QuickBooks Desktop SDK responses: accounts (with `TaxLineInfoRet/TaxLineName` → `SourceAccount.TaxLine`, mapped on import by `TaxLines.FromName(name, form)`: the words after the colon, a unique best match or nothing), customers, vendors, items, journal entries; jobs and other transactions are reported, not imported), `QuickBooksOnlineReader` (QBO API query JSON; journal lines resolve accounts by id), `GnuCashReader` (XML book, gzip or not; split values are fractions; an account whose type differs from its parent's starts a new top-level branch because OpenBook subaccounts share their parent's type; other currencies are refused), `XeroReader` (chart, contacts or manual journal CSV, recognized by columns), `WaveReader` (accounting transactions CSV) and `FreshBooksReader` (clients CSV). XML is loaded with DTDs prohibited and no resolver; elements are matched by local name with `Named`/`Child`/`Text` (don't call `XDocument.Descendants(string)`, which needs the namespace).
- Page `/import/migrate` (also `/import/quickbooks`, accountant) and `POST /api/import/migrate/{source}` with the raw file as the body (`?dryRun=true` previews). No live QuickBooks Online OAuth connection: the API JSON is saved and uploaded.
- Scheduled backups: `BackupSchedule` (singleton row: daily or weekly at an hour in the company's time zone, folder or S3-compatible destination, keep N; the secret key protected by `ISecretProtector` and left out of the data export and audit) and `ScheduledBackupService` (settings, `RunDueAsync`, `RunNowAsync`; outcome kept on the schedule). A run is due when nothing has run since the latest slot, so the first one runs right away, or when the last failed an hour ago and fewer than `BackupSchedule.Retries` (5) tries followed the slot. Each copy is checked first (`IBackupService.CheckAsync`: the restore checks) so a damaged file never rotates good ones out; `BackupSchedule.IsFailing` (last run failed, or the last success older than two periods plus a day) shows on Settings and the home to-do list. Targets are `IBackupTarget`s in `Infrastructure/Backups`: `FolderBackupTarget` (write then rename) and `S3BackupTarget` (path-style requests signed by `AwsSignatureV4`, tested against the AWS example). Only files named `openbook-scheduled-{company}-*` of this company are ever deleted (the first 8 of its id; names from before that are left alone). `ScheduledBackupHostedService` checks every 15 minutes. SQLite only, like manual backups. UI on `/backup` (admin), API `/api/backup/schedule`. Audit entity type `backup_schedule`.

## Desktop and Server (L13)

- One build, two installs: `OpenBook:Install` = `Desktop` or `Server` (default), else `openbook.install.json` (`{"Install": "Desktop"}`) beside the app, which the desktop package ships so its commands (`reset-password`, …) act on the desktop company too. `Web/Hosting/Installation` (singleton, read once in `Program.cs`) is the one place that knows; code says "install", never "edition" (L11's industry editions). It decides files, defaults and page wording only, never data or rules.
- Desktop: company file `Documents/OpenBook/openbook.db` (`OpenBook:Desktop:DataFolder` moves the folder), backups in its `Backups` subfolder, Data Protection keys (`keys`, unencrypted at rest like Docker's so they can travel with the file), logs and `running.json` in local app data (`OpenBook:Desktop:AppFolder`); the connection string, backup, key and log settings are ignored, and the provider is always SQLite (`OpenBook:EncryptionKey` still applies). `DesktopHost`: a named mutex per data folder; a second start waits for `running.json`'s address to answer `/healthz`, opens the browser there and exits 0; Kestrel listens on localhost only (`ListenLocalhost`) on `OpenBook:Desktop:Port` (5180) or a free port; once started it writes `running.json` and opens the browser (`OpenBook:Desktop:OpenBrowser=false` for tests and previews), and deletes the file when stopping. `POST /settings/system/quit` (admin, desktop only, else 404) stops the app.
- Desktop backups: `ScheduledBackupService.SetUpDefaultAsync(folder)` saves an enabled daily schedule (noon, `DefaultHour`, keep 14) when none exists (audited `Created`, actor "system"); `ScheduledBackupHostedService` calls it on desktop, checking every minute until a company exists, then runs due backups at once and every 15 minutes.
- Pages: the System page has a desktop variant (company file, folders, Quit; no database, key or network facts); the Backup page shows pg_dump/pg_restore guidance (host, database and user from the connection string, never the password) instead of download/schedule/restore when the provider is PostgreSQL; `<DesktopNote>` explains on desktop only where something needs others to reach OpenBook (invitations, portal links, capture devices, Stripe webhooks). Nothing is hidden or refused. The Docker image sets `OpenBook__Install=Server`.
- Packaging (Windows only so far): `src/OpenBook.Desktop` (assembly `OpenBook.Desktop`, WinExe, icon `packaging/windows/openbook.ico` from `tools/make-icon.py`) starts `OpenBook.Web.exe` beside it with no window, waits until `running.json` is written or the server exits (exit 0 = handed over), and shows a message box if it fails; then it stays as the tray icon (`TrayIcon`, WinForms, `net10.0-windows` with `EnableWindowsTargeting` so Linux builds still restore; one per running file, by mutex): Open OpenBook, Back up now, Quit OpenBook. It talks to the server through `DesktopControlService` (Web/Hosting/DesktopControl.cs): a named pipe `DesktopHost.ControlPipe` (written to `running.json` as `Control`) created with `PipeOptions.CurrentUserOnly`, one line each way: `backup` → `ok {file}` / `none` / `failed {reason}`, `quit` → `bye`, then stop. Quitting (tray, or Settings > System's Quit) backs up first through `DesktopQuit` and `ScheduledBackupService.RunBeforeQuitAsync` (to the schedule's destination, `QuitPrefix` = `openbook-scheduled-quit-`, last `QuitKeep` kept; the daily rotation only counts names with a timestamp right after `NamePrefix`); the tray asks before quitting when that fails. The icon leaves when `running.json` goes. `tools/package-desktop.ps1 [-Version] [-SkipInstaller]` publishes both self-contained (win-x64) into `artifacts/desktop/win-x64`, writes `openbook.install.json`, drops `appsettings.Development.json`, and runs Inno Setup (`ISCC.exe` from `%LOCALAPPDATA%\Programs\Inno Setup 6`, Program Files or PATH) on `packaging/windows/OpenBook.iss`: per-user (`{localappdata}\Programs\OpenBook`, no admin), fixed `AppId` (never change it), Start menu (and optional desktop) shortcut, `CloseApplications=force` so updates and uninstalls stop the running server, old program files deleted on update; Documents and local app data are never touched. Desktop add-ins live in local app data `plugins` (`Installation.PluginsFolder`) because updates replace the program folder. Unsigned. Admin docs: `docs/admin/desktop.md`, `docs/admin/server.md` (compose, HTTPS behind Caddy/nginx with WebSockets and forwarded headers, Data Protection keys and what they protect, pg_dump schedules and restore, moving a desktop company in with `docker compose run … move-to-postgres`).
- Updates (`Web/Hosting/Updates.cs`, `Application/Updates`): releases publish the installer and `latest.json`, an `UpdateManifest` (version, url, sha256, size, minimum version, notes, published) signed with ECDSA P-256 over `SignedText`; the app trusts only `UpdateKeys.PublicKey` (through the `UpdateTrust` singleton, which only tests replace). The private key is never in the repository (`%USERPROFILE%\.openbook-release\update-signing-key.pem`, the `OPENBOOK_UPDATE_KEY` Actions secret); `src/OpenBook.ReleaseTool` does `keygen` / `manifest` / `verify`. `UpdateService` (singleton): `OpenBook:Updates:Feed` (default the GitHub releases' latest `latest.json`; HTTPS only, plain HTTP only on loopback), checking on by default only for an installed desktop copy (install file beside the app; `OpenBook:Updates:Check`; the desktop's own choice in `AppFolder/updates.json`), `CheckAsync` (signature, newer by `UpdateVersion`, desktop downloads to `AppFolder/updates` and checks size and hash), `InstallAsync` (desktop: `DesktopQuit.BackUpAsync`, refused on a failed backup unless told otherwise, then `IInstallerLauncher` runs the installer `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /CLOSEAPPLICATIONS /RELAUNCH=1 /LOG=…` with `OpenBook__Desktop__*` environment variables so the copy it restarts keeps its folders, then stops). `UpdateCheckService` checks a minute after start and daily. The pipe adds `update` and `install`/`install-anyway`; the tray shows "Install OpenBook x.y.z". The installer's `[Run]` entry with `Check: Relaunch` starts OpenBook after a `/RELAUNCH=1` install; `package-desktop.ps1 -TestAppId` builds a test installer (own AppId and name, no shortcuts) for trying updates. Releases: `.github/workflows/release.yml` on a `v*` tag (tests, Inno Setup from Chocolatey, package, sign the manifest, `gh release create`); `docs/admin/releasing.md`. A server only reports updates (new source, `docker compose build --pull`, `up -d`; no image is published).
- Moving to PostgreSQL: `PostgresMove` (Infrastructure/Persistence) behind the `move-to-postgres` command (`Web/Cli/MoveToPostgresCommand`). It copies the SQLite file (and any `-wal`) to a temp folder, since the app is stopped and a container may not be able to write beside it, validates it with the restore checks (`SqliteBackupService.ValidateAsync`, now static) and migrates the copy; migrates the target and refuses unless every table is empty (`move.target_not_empty`); copies every table of the EF relational model in foreign-key order (a cycle between tables throws: teach it before adding one; self-referencing rows are buffered and written parents first) inside one PostgreSQL transaction, reading each column through the SQLite property type mapping and writing through the PostgreSQL one (`DateTimeOffset`s to UTC). `JournalEntries` go in with `IsSealed` false and one `UPDATE … SET "IsSealed" = TRUE` lets the seal trigger check every entry; identity sequences are `setval` past the copied ids. Columns named `Protected*` are secrets: unprotected with the source keys' `ISecretProtector` and protected with the target's; one that can't be read stops the move (`move.secret_unreadable`). So a new secret column must be named `Protected…`. Before committing: row counts per table, unbalanced or unsealed entries, balance per account, audit count and last id, and the ledger triggers (`SqliteLedgerTriggers.Names`) present; then a `Restored` audit record on the company (actor `console:{user}`, `MovedFrom` = file name). A desktop copy that's running refuses the move of its own file.
- Tests: `InstallationTests` (paths, install file, port fallback, desktop web app with default schedule and pages, quit only on desktop); `PostgresMoveTests` (PostgreSQL only: a company with self-referencing rows, a void and a two-factor secret moves whole, posts and keeps its triggers afterwards, a second move is refused; unreadable secrets leave the target empty). `tools/run-tests.ps1` strips single or double quotes from `.env` values.

## QuickBooks Desktop export helper

- `src/OpenBook.QuickBooksExport` (no project references, net10.0, published win-x86 single-file, uncompressed: VIPRE quarantined the compressed self-extracting build) runs where QuickBooks Desktop has the company open, so a .QBW (or a .QBM/.QBB restored in QuickBooks) moves in; OpenBook never reads company files itself. `RequestProcessorSession` drives QuickBooks' own `QBXMLRP2.RequestProcessor` late-bound (`dynamic`, Windows only; HRESULTs explained in `Explain`, always with QuickBooks' message). `QuickBooksExporter` (tested through `IQuickBooksSession` with `FakeQuickBooks` in `QuickBooksExportTests`) picks the newest qbXML version ≤ 16.0 (≥ 3.0 required; iterators from 5.0), asks CompanyQuery, AccountQuery (`ActiveStatus` All), Customer/Vendor/ItemQuery in pages of 500, and the Journal report (`GeneralDetailReportQueryRq`, columns `JournalColumns`) per month from `--to` back to `--from`, or until 60 empty months; a month too big for a file is halved by dates. Statuses: code 1 = nothing found, other errors stop. Files: company + accounts in each, list pages then months in date order, each under `MaxFileBytes` (19 MB; the import takes 20 MiB), named "{company} - for OpenBook[ - part i of n].qbxml". `ExportCommand.Run` is the command line (exit 0 / 1 QuickBooks / 2 options); double-clicked it uses Documents\OpenBook QuickBooks export and waits for Enter.
- Reader side: `QbxmlJournal` reads a `ReportRet` with Account, Debit and Credit columns (found by `ColType`): rows group by TxnID (else TxnNumber), rows without one continue the transaction, subtotal rows end it; all-zero transactions are skipped. Report account names ("1000 · Checking", "6000 · Utilities:6010 · Phone", a bare leaf) resolve to the file's AccountRet full names (`AccountNames`). When a file has a journal report, `QbxmlReader` takes every transaction from it and ignores `JournalEntryRet`s.
- The web app offers it at `/import/quickbooks-export` (accountant, `/import` rule) when `QuickBooks/OpenBook.QuickBooksExport.exe` is beside the app (`Hosting/QuickBooksHelper`); the installer adds a Start menu entry "OpenBook - Export from QuickBooks". The Docker image doesn't include it yet.
