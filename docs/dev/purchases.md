# Purchases and payables

Developer notes moved out of `CLAUDE.md` (index there). Read this file before changing this area; keep it up to date in the same commit.

## Purchases (M4)

- `Vendor` mirrors `Customer` (plus your account number with them and a default expense category that pre-fills bills and expenses). Vendors with unpaid bills can't be deactivated.
- `Bill` lines are category lines (account, description, amount; negative = credit), not items; any active account except A/R and A/P. Bills post Dr categories / Cr the first A/P account (created and saved on first use). Bill numbers are the vendor's, unique per vendor. A bill with payments can't be voided. `BillService.ChangeAsync` corrects a bill in place like `InvoiceService.ChangeAsync` (entry voided and reposted, stock reversed and received again, which `PlanReversalAsync` refuses once a layer is used; vendor fixed; total ≥ `AmountPaid`; bill payment dates must be open when the postings per account and class change); bills from a purchase order go through `PurchaseOrderService.ChangeBillAsync` instead (the public `ChangeAsync` refuses them, `bill.from_order`). Lines marked billable (`BillableExpense.LineNumber`) must stay unchanged on the same line; other lines renumber and their custom field values move. Approval runs again (`Bill.Rehold`: held again, even if approved, with the changer as `EnteredBy`). History through the shared `DocumentChanges` (audit `ChangeReason`) and `<DocumentChangeList>`. Page `/purchases/bills/{id}/edit`, API `PUT /api/purchases/bills/{id}`.
- Possible duplicate bills (2026-11-03): `BillService.PossibleDuplicatesAsync(vendor, date, total, except)` (posted, same total, within `DuplicateDays` = 14); the new bill form shows them and turns its button into "Save anyway" until the vendor, total or date changes. API `GET /api/purchases/bills/duplicates`. Nothing is refused.
- `BillPaymentService.PayAsync` takes any open bills across vendors and writes one `BillPayment` per vendor (and per A/P account) in one save, vendors in name order; numeric check numbers count up from the first. Paid from a Bank or Credit card account. The vendor's account number is the default memo. `BillPaymentService.ChangeAsync` corrects one in place like a customer payment (applications replaced among the same vendor's bills on the same A/P account, bills audited; an issued payment (printed, `AchBatchId`, or sent by positive pay) keeps amount, account and reference; a feed-matched one keeps amount and account, and the match follows). Page `/purchases/payments/{id}/edit`, API `PUT /api/purchases/payments/{id}`.
- Vendor deposits (`VendorDeposit`, Domain/Purchases; audit `vendor_deposit`, Versioned; `Source = purchases.vendor_deposit`: Dr "Vendor Deposits" (other current asset, created on first use) / Cr the bank or card; optional `PurchaseOrderId`): `VendorDepositService.ApplyAsync` writes bill payments from that account through `BillPaymentService.PayFromDepositAsync` (`BillPayment.VendorDepositId`; such payments can't be changed, `payment.from_deposit`, only voided), so bills, aging and cash basis treat them as payments. `Remaining` = amount − posted payments from it; void only while unused. Pages `/purchases/vendor-deposits`, `/{id}`; posts `/purchases/vendor-deposits`, `/{id}/apply` (`bill:{id}` amounts), `/{id}/void`; API `/api/purchases/vendor-deposits` (+ `/{id}/apply`, `/{id}/void`). In the books check's other documents.
- `BankingService.CheckNumberUsedAsync` (the spend form's "Save anyway"; nothing is refused). Expenses (paid immediately) are `BankTransaction` spends with an optional `VendorId`; the payee defaults to the vendor's name. A spend may also come from the owner's own money (`BankingRules.EnsurePayFrom`/`IsOwnMoney`: equity, other current or long-term liability; spends only): `BankingService.OwnMoneyAccountAsync` finds or adds the equity "Owner Contributions", `POST /banking/paid-personally` opens its spend form, which then links to `/accounts/{id}/register`. Check-number suggestions count both expense and bill-payment references.
- `DocumentStatus` (Posted/Voided) is shared by sales and purchase documents; `Text.Optional` lives in Domain.Common.

## Payables (V1.4)

- `VendorCredit` posts the mirror of a bill (Dr A/P, Cr categories) and reuses `BillLine`. `VendorCreditService.ApplyAsync` applies credit to the vendor's bills without posting (applications carry `AppliedOn`); `VendorRefund` records money the vendor pays back (Dr bank, Cr A/P). A bill's `AmountPaid` includes applied credits. `VendorCreditService.ChangeAsync` corrects a credit in place like a credit memo (vendor fixed; total ≥ applied + refunded; date no later than the first application; refund dates open when `BillService.SamePostings` says the postings changed). Page `/purchases/vendor-credits/{id}/edit`, API `PUT /api/purchases/vendor-credits/{id}`.
- `RecurringBill` stores bill line drafts and uses `Recurrence`; `RecurringBillService.CreateDueAsync` enters each bill through `BillService` (recorded as `Bill.RecurringBillId`). The hourly `RecurringPostingService` runs automatic ones.
- `PayablesService`: A/P aging (like A/R, from the documents) and the 1099 summary. 1099 totals are bill payments and vendor expenses dated in the calendar year, excluding card accounts (1099-K); vendor refunds show beside them (`Vendor1099.Refunds`), and come off them only with `PurchasingSettings.Net1099Refunds` (off by default; a tax question each business answers), bank refunds off the total and card refunds off the card column. `Filing1099CsvAsync` takes a `threshold`. `DefaultThreshold`: $600 through 2025, $2,000 from 2026 (later years are inflation-indexed; the report takes an override).
- `Filing1099Service`: vendors' copies (a `DonorLetter` per vendor, PDF at `/accountant/1099/copies`, emailed as `EmailKind.Form1099Copy`), W-9 requests (`EmailKind.W9Request`), `Filing1099` rows (a note of what was filed, per year and vendor, audited `filing_1099` on the company) and `MissingTaxIdsAsync` (the January to-do). `Prior1099Payment` (table `Prior1099Payments`, one per vendor and year, posts nothing; `Filing1099Service.SetPriorAsync`, audited `Updated` on the vendor) is what was paid before OpenBook: added to the reportable total (`Vendor1099.Prior`); `Report1099.HistoryImported` when `ledger.import` entries fall in the year. Form `/accountant/1099/prior`, API `GET|PUT /api/accountant/1099-prior[/{year}]`. The filing file splits addresses with `AddressParts` and carries `Company.TaxId` (the EIN, under Company details). OpenBook doesn't file with the IRS.
- Vendors have `Track1099`, `TaxId` (normalized EIN/SSN) and `Form1099Box`; the vendor CSV import reads all three (`VendorImportService.ParseBox`; the preview's rows carry the tax ID masked). `Account.Excluded1099` ("Not reportable on 1099s", any account, `Create/UpdateAccountCommand.Excluded1099`): expense categories on it, and each bill payment's share of the bills' lines on it, come off `Vendor1099.Total` into `NotReportable` (bank payments only; card payments are 1099-K anyway). The tax ID is never shown or returned in full: use `MaskedTaxId`; in `VendorDetails` a null `TaxId` keeps the saved one and "" clears it.
- A button that asks first takes `data-confirm="…"` (handled in `shortcuts.js`), never an inline `onclick` with a value in it: HTML encoding doesn't stop a name becoming script there.
- Attachments (`Domain/Attachments`): metadata in `Attachments`, bytes in `AttachmentContents` (cascade delete), in the company file. The content type comes from the extension (`Attachment.AllowedTypes`: no HTML/SVG/scripts); only images and PDFs are served inline, always with `X-Content-Type-Options: nosniff` and a sandboxing CSP. Uploads go through the web form endpoint `/attachments` (antiforgery), not the cookie API. `AttachmentService.EntityTypes` lists what can take files (now also grant, donation, pledge, fixed_asset, loan, project), `EfAttachmentStore.ExistsAsync` must know each type and `RecordAreas.Of` its area. Adding/removing writes `Attached`/`Detached` audit records on the owning record. Put `<Attachments EntityType=… EntityId=… />` on new detail pages.
- `SalesLinesEditor.Also` takes lines the document has besides the grid's (billed time and costs): they count in its totals and tax.
- `BillLinesEditor`/`BillLineModel` (Components/Purchases) is the shared category grid for bills, vendor credits and recurring bills.

## Purchasing controls (L3, slice 3)

- Bills from an order: `Bill.LinesFromOrder` says how many of its lines came from the order (null on older bills, which plan it again); a zero-cost item line goes on a bill and into stock at no value (no posting); hold reasons are cut to fit (`HoldText`). An order with priced goods received and not billed can't be cancelled (`purchaseorder.received_not_billed`). Inbox documents: lines for one order item add up to one order line at the printed amounts (`Amount / Quantity` to 4 decimals). `ReceiptService.RecordAsync` is one transaction, and `ReceiptCapture` is `Versioned`.
- `PurchaseOrder` (Domain/Purchases/PurchaseOrder.cs; audit `purchase_order`, attachments allowed; own number sequence; `VendorAddress` kept when made or when its vendor changes, older ones filled on their next save, printed in place of today's): owned `PurchaseOrderLines` (an inventory item, not an assembly, with quantity and unit cost to 4 decimals; or a category line with an amount) and `PurchaseOrderReceipts` (rows per line grouped by `ReceiptNumber`, voidable). Posts nothing; receiving posts nothing either (stock enters the books with the bill). Open → Closed (everything billed) / Cancelled; editable until anything is received or billed.
- Bills from a PO: `PurchaseOrderService.CreateBillAsync(id, BillFromOrderCommand)`; lines given (quantity + the vendor's unit cost, or a category amount) or, by default, what's received and not billed (everything left when nothing is received). The bill records `PurchaseOrderId` and owned `BillSourceLines` (line, quantity, amount); billed totals come from posted bills, so voiding frees them and reopens a closed PO. 3-way match differences (billed more than ordered; more than received when `RequireReceipt`; unit cost, or a category line's running total, over the order beyond `PriceTolerancePercent`) go to `BillService.CreateAsync(..., BillSource)` as hold reasons. The lines are worked out by `PlanBillAsync`; `ChangeBillAsync(billId, ChangeBillFromOrderCommand)` plans a posted bill again against `ProgressAsync(order, except: bill)` (so accruals and the match see only the order's other bills) and changes it through `BillService.ChangeFromSourceAsync` (new source lines, holds rerun, the order closed or reopened); cancelled orders are refused. `BillPartsAsync` takes a bill apart into order picks (unit cost = amount / quantity) and extra lines (the bill's lines after those the picks plan to). The bill's Change page shows `BillFromOrderEdit` for these; API `GET|PUT /api/purchases/bills/{id}/from-order`.
- Receiving into stock (`PurchasingSettings.ReceiveIntoStock`, off by default; `PurchasingSettingsCommand.ReceiveIntoStock` null keeps it): `PurchaseOrderService.ReceiveAsync` also plans the delivery like bill item lines (`InventoryService.PlanPurchaseAsync`, the order's unit costs and warehouse; lot/serial items refused because they need numbers) and posts `Source = purchases.receipt` (`SourceId` = the delivery's `StockSourceId`, movements `InventorySources.PurchaseReceipt`): Dr each item's asset / Cr "Received Not Billed" (other current liability, created on first use). Receipt rows keep `StockSourceId`, `JournalEntryId`, `Value`; `PurchaseOrder.InStock(line)`. A bill from the order bills units already in stock as category lines: Dr "Received Not Billed" at their received value (the remainder of the line's value when it clears the line) plus the cost difference to "Purchase Price Variance" (cost of goods sold); units beyond go in as item lines. `BillSourceLine.AccruedQuantity/AccruedAmount` record this, so voiding the bill frees them. Taking a delivery back reverses its stock and entry, refused once its units are billed or its layer used. Landed costs reach layers opened by bills and, for a bill from a purchase order, the layers its order's deliveries received into stock (`LandedCostService.DeliveriesAsync`; each line keeps the bill). Spreading by weight or volume, or over chosen lines, isn't done. Bills ahead of deliveries (`StockedRowsAsync`): a line needs in stock from deliveries what's received less `BilledIntoStock`, so a delivery leaves out units a bill brought in, on rows of their own (`PurchaseOrder.SplitReceipt`; `InStock` false, `Value` 0), and needs no schema of its own. `PlanBillAsync` keeps such units as item lines, a bill that would drop them is refused (`EnsureDeliveriesCovered`, `purchaseorder.delivery_counted_on`, only with receiving into stock on), and so is taking back a delivery a later one counted on (`purchaseorder.receipt_counted_on`). A closed order still receives goods, and takes deliveries back; only a cancelled one refuses.
- Approvals: `PurchasingSettings` (one row; audit `purchasing_settings`): `ApprovalThreshold` (bills with total ≥ it are held), tolerance, `RequireReceipt` (default on), `AllowSelfApproval` (default off). Every bill records `EnteredBy` (the actor); `Bill.Approval` NotRequired / Pending / Approved / Rejected with `HoldReason` (one reason per line), `ApprovedBy/At`, `ApprovalNote`. Existing bills were backfilled NotRequired. `BillPaymentService.PayAsync` refuses bills that aren't `CanBePaid` (`bill.not_approved`). `BillApprovalService` approves (from Pending or Rejected) or rejects (note required); the person who entered a bill can't decide on it unless self-approval is on. Rejected bills are voided the usual way.
- ACH: `VendorBankAccount` (one per vendor; routing number checked with the ABA check digit; account number stored through `ISecretProtector`, shown as last four, excluded from the data export; changes audited on the vendor without the number). `AchSettings` per Bank account (bank routing = immediate destination and ODFI, origin, company ID/name, entry description). `AchService.CreateFileAsync` takes posted bill payments from that account to vendors with bank details, not printed as checks, not sent before and not matched or reconciled (the page leaves them unticked and shows the reference: Pay Bills fills in a check number by default, so a number can't rule one out), builds a NACHA file with `Ach.Build` (one CCD batch of credits, service class 220, codes 22/32, trace numbers ODFI + sequence, entry hash, padded with 9s to blocks of ten, CRLF), stores it encrypted on an `AchBatch` (`ProtectedContent`, read with `AchService.FileText`; older or restored files in clear are in `UnprotectedContent`, column `Content`, until the hourly job's "ACH files" step encrypts them and wipes what they left in the database; audit `ach_batch`; file ID modifier A–Z then 0–9 per account per day) and sets `BillPayment.AchBatchId`. `WithdrawFileAsync(batch, reason)` (a file the bank never got: `AchBatch.WithdrawnAt`/`WithdrawReason`, its payments' `AchBatchId` cleared and audited, refused once one has cleared the bank, `ach.payment_cleared`; a withdrawn file can't be downloaded); `FilesAsync` counts each file's payments voided since, which the page flags. Form `/purchases/ach/files/{id}/withdraw`, API `POST /api/purchases/ach/files/{id}/withdraw`.
- Pages: `/purchases/orders`, `/purchases/orders/new`, `/purchases/orders/{id}/edit`, `/purchases/orders/{id}` (receive goods, take a receipt back, enter the bill, cancel); `/purchases/approvals` and `/purchases/approvals/settings` (accountant); `/purchases/ach` (accountant: bank details per account, payments to send, files, download at `/purchases/ach/files/{id}`); `VendorBankDetails` on vendor pages (form posts to `/purchases/ach/vendors/{id}`, accountant). `PurchaseOrderForms` renders a PO as a `SalesForm` (`PartyLabel` "VENDOR") at `/purchases/orders/{id}/pdf` and emails it (`/purchases/orders/{id}/email`, audit `Emailed` on the order; API `/api/purchases/orders/{id}/pdf|email`). Bill pages show the PO, approval and hold reasons; pay bills shows held bills unticked. Form posts in `Web/Endpoints/PurchasingEndpoints.cs`; API under `/api/purchases` (`/orders`, `/approvals`, `/ach`).

- Reordering (2026-11-03): `Item.PreferredVendorId` (any item; an inactive vendor only if it was already chosen) and `Item.ReorderQuantity` (inventory only, > 0). `Item.LeadTimeDays` (0–365) and `StockOutlook.SoldPerMonth` (sale-source movements net of returns over `ReorderService.SalesDays` = 90, per 30 days): `LeadTimeDemand`, `CoverDays`, and `NeedsReorder` also when projected ≤ lead-time demand; `Suggested` is the larger of the point's gap and lead time plus a month of sales less projected (when no reorder quantity). `ReorderService.OutlookAsync(warehouse?)` gives each active tracked item's `StockOutlook`: on hand, on open purchase orders (ordered less what came into stock: received into stock plus billed item units), on open sales orders (not invoiced yet; bundles as components), `Available`, `Projected`, `NeedsReorder` (projected ≤ reorder point) and `Suggested` (the reorder quantity, else whole units to get back above the point). `CreateOrdersAsync` makes one PO per vendor (name order, memo "Reorder") in one `IUnitOfWork` transaction. The stock status report shows these columns. Page `/purchases/reorder` (posts `pick`, `vendor:/qty:/cost:{itemId}` to the same path in `PurchasingEndpoints`); API `GET|POST /api/purchases/reorder`.

## Document inbox

- `CapturedDocument` (Domain/Documents; audit and attachment entity type `captured_document`; owned `CapturedDocumentLines`): a vendor invoice, customer PO, packing slip or vendor quote (`DocumentKind`; `DocumentKinds.IsFromVendor`, `HasPrices`) with the file attached, what was read (party name as printed, number, dates, `OrderReference` = our PO number on vendor documents, totals, lines with code/description/quantity/unit price/amount) and the matches (`VendorId` or `CustomerId`, `PurchaseOrderId`, each line's `ItemId`). New → Done (`ResultType`/`ResultId`, set by the later slices) or Dismissed (`Restore` puts it back). `Read` stores a reading leniently (cuts and rounds what nobody typed); `Review` checks a person's corrections strictly.
- `DocumentCaptureService.UploadAsync(kind, fileName, stream, useClaude)` checks the file like an attachment, saves it, reads it and matches it; `ReadAgainAsync` replaces the fields (and corrections). Reading: Claude when `DocumentReadingSettings.IsReady` (one row, admin page `/settings/document-reading`, audit `document_reading_settings`; API key through `ISecretProtector`, left out of the export and audit; model default `claude-opus-5-5`) and the uploader didn't untick it; on any `DocumentReadException` it falls back to the server and says why in `ReadNote`. Server: `IReceiptTextExtractor` text, then `DocumentParser` (Domain: labelled references, dates, totals, item lines from trailing numbers where quantity × price = amount; packing slips need a product code or ordered/shipped columns). `DocumentMatching`: party by name, PO by number ignoring prefixes ("PO-1004" = "1004"), items by barcode/name, PO line description, then the longest item name inside the description.
- `DocumentItemCode` (table `DocumentItemCodes`, unique per party and code): a conversion (`DocumentConversionService.FinishAsync` → `DocumentCaptureService.LearnCodesAsync`) remembers the item on each coded line it used as that vendor's or customer's code, never a review; matching tries learned codes first. `ItemCodesAsync`/`ForgetItemCodeAsync` (audited `Updated` on the party) behind `<LearnedCodes>` (Components/Documents) on vendor and customer pages, posting `/documents/item-codes/{id}/forget`.
- Conversions belong to the area of what they make, not `documents` (`ApiScopes.DocumentConversionArea`, for permission sets and scoped keys alike). The review form has `data-unsaved-watch` and the make forms `data-needs-saved`: `shortcuts.js` asks before making from a document with unsaved changes.
- `DocumentConversionService` (each in one `IUnitOfWork` transaction; copies the file onto the record, marks the document Done with an `Updated` audit): `MakeBillAsync` (vendor invoice; with a PO, lines with the order's items, or a category line with the same description, bill the order's lines through `PurchaseOrderService.CreateBillAsync` and everything else goes in `BillFromOrderCommand.Extra`, outside the 3-way match; without one, a plain bill: inventory items into stock, other lines to `DocumentAccounts` (per line, default, else the vendor's default category); tax and shipping become "Sales tax" / "Shipping" lines; refused when the lines, tax and shipping don't add up to the document's total), `MakeSalesOrderAsync` (customer PO; the document's prices, `AutoPrice` where there's none; their PO number as `CustomerReference`; priced lines need an item, unpriced ones without become notes), `ReceiveAsync` (packing slip; each line to the first order line with its item and something left to receive; note "Packing slip …") and `MakePurchaseOrderAsync` (quote; inventory items as item lines, the rest as category lines; memo "Quote …"). The review page's "make" panel posts to `/documents/{id}/bill|sales-order|receive|purchase-order` (closing password supported); API `POST /api/documents/{id}/bill|sales-order|receive|purchase-order`.
- Uploads (2026-11-03): the inbox and receipts take several files in one post (`file` repeated, `DocumentEndpoints.MaxFiles` = 10, `RequestSizeLimit` `MaxUploadBytes`; one file opens its page, several go back with `uploaded=n` and per-file refusals); both endpoints bind `IFormCollection` so the antiforgery check runs. `CapturedDocument.FileHash` / `ReceiptCapture.FileHash` (SHA-256 hex, indexed; null for older rows). `DocumentCaptureService.DuplicatesAsync` (same file in the inbox or receipts, a posted bill from the vendor with the document's number, bills for the same total within `BillService.DuplicateDays`), `NextWaitingAsync`; `ReceiptService.SameFileAsync`. `UploadAsync(..., purchaseOrderId)` falls back on that order (or the one chosen before, on read again) when reading finds none; PO pages link `/documents?kind=VendorInvoice|PackingSlip&order={id}`. API `?purchaseOrderId=`, `GET /api/documents/{id}/duplicates`. Home to-do: documents to check, receipts to record.
- `ClaudeDocumentReader` (Infrastructure/Documents, official `Anthropic` SDK, Apache-2.0): file as a PDF/image/text block, structured output against a fixed JSON schema, effort medium, server-side refusal fallback for models that take it; `Parse` maps the JSON. Tests use `FakeClaude` (registered by `LedgerDatabase`).
- Pages `/documents` (upload: multipart, kind, "Read it with Claude"; list) and `/documents/{id}` (file preview, editable fields and lines posting `desc:i/sku:i/qty:i/price:i/amount:i/item:i` + `rows`, read again, dismiss/restore); form posts in `Web/Endpoints/DocumentEndpoints.cs`. API `/api/documents` (upload takes the raw body with `?kind=&fileName=&claude=`), `/api/settings/document-reading` (admin); scope area `documents`.
- Fuzzing (2026-11-12): `DocumentParser` reads a number as a word unless it's 0 or between 0.0001 and `Money.MaxAmount` (`Plausible`), so quantity × price and amount ÷ price can't overflow.
